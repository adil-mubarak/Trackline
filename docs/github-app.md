# Optional GitHub App integration

The AI service can provide an authenticated repository picker and read-only pull-request evidence. Configure `GITHUB_APP_ID`, `GITHUB_INSTALLATION_ID`, and `GITHUB_PRIVATE_KEY` in the deployment environment; `GITHUB_API_URL` defaults to `https://api.github.com`. The PEM private key can be supplied with literal `\n` separators. Do not commit credentials. `GITHUB_EVIDENCE_TO_OPENROUTER` defaults to `false`; keep it false until the organization has approved sending this evidence to OpenRouter.

Install the App only on repositories users may connect. Grant **Metadata: read-only**, **Pull requests: read-only**, and **Checks: read-only**. No Contents permission is required or used. The integration requests an installation token on demand and never sends App credentials or GitHub tokens to the browser or OpenRouter. Without all credentials, the chat feature remains available and does not advertise GitHub evidence tools; directly requested GitHub endpoints return 503. The repository picker can be enabled with App credentials while the evidence tool remains disabled until the separate OpenRouter opt-in is set to `true`.

Authenticated clients can call `GET /github/repositories` through the Gateway to populate a project repository picker. The Project service verifies selected repository IDs through the AI service's network-internal `GET /internal/github/repositories/{id}` endpoint; do not publish the AI service port outside the trusted service network. Only pull requests explicitly linked to an issue are eligible for evidence, and the linked repository must match the project's connected repository. Evidence contains selected PR metadata, up to 10 reviews and 10 check-runs per PR, and is capped at five linked PRs and 20 KiB. No source or diff content is read.

The Issue service exposes explicit links at `GET /issues/{id}/pull-requests`; each includes the canonical repository ID and PR number. The `linked_pr_evidence(project_id, issue_id)` MCP tool confirms the issue belongs to the supplied project and that each link matches the project's currently connected repository before making any GitHub call.
