# Optional GitHub App integration

The AI service can provide an authenticated repository picker, read-only pull-request evidence, and an optional bounded diff-review tool. Configure `GITHUB_APP_ID`, `GITHUB_INSTALLATION_ID`, and `GITHUB_PRIVATE_KEY` in the deployment environment; `GITHUB_API_URL` defaults to `https://api.github.com`. The PEM private key can be supplied with literal `\n` separators. Do not commit credentials. `GITHUB_EVIDENCE_TO_OPENROUTER` and `GITHUB_CODE_TO_OPENROUTER` default to `false`. Enable each only after separately approving the corresponding metadata or source-diff processing by OpenRouter.

Install the App only on repositories users may connect. Grant **Metadata: read-only**, **Pull requests: read-only**, and **Checks: read-only**. The diff tool uses GitHub's pull-request-files endpoint; it does not call the Contents API, crawl the repository, or access arbitrary files, so Contents permission is not needed for this feature. Remove Contents permission unless another approved integration needs it. The integration requests an installation token on demand and never sends App credentials or GitHub tokens to the browser or OpenRouter. Without App credentials, the chat remains available but no GitHub tools are advertised. The repository picker can be enabled with App credentials while each model-facing tool remains disabled until its separate OpenRouter opt-in is set to `true`.

Authenticated clients can call `GET /github/repositories` through the Gateway to populate a project repository picker. The Project service verifies selected repository IDs through the AI service's network-internal `GET /internal/github/repositories/{id}` endpoint; do not publish the AI service port outside the trusted service network. Only pull requests explicitly linked to an issue are eligible, and the linked repository must match the project's connected repository. Metadata evidence contains selected PR metadata, up to 10 reviews and 10 check-runs per PR, and is capped at five linked PRs and 20 KiB.

When `GITHUB_CODE_TO_OPENROUTER=true`, an explicit code-review request naming exactly one issue (for example, “review code changes in issue #35”) triggers authenticated, server-side prefetch of bounded changed-file patch excerpts for PRs linked to that issue. The issue/project/repository and PR links are resolved and checked through their owning APIs before fetching GitHub data; the model does not choose or execute the retrieval call. It is not a general code browser: at most five linked PRs and 10 changed files total are considered, generated/vendor/build/secret-like paths are omitted, and the serialized result is capped at 16 KiB with per-file truncation. Likely credential assignments and recognizable token formats are redacted; this is defense-in-depth, not a guarantee that all secrets are detected. Binary files, full file contents, arbitrary branches, and repository-wide search are never requested. Treat code as untrusted input and verify any AI review finding in GitHub. Do not log or persist source excerpts.

The Issue service exposes explicit links at `GET /issues/{id}/pull-requests`; each includes the canonical repository ID and PR number. The `linked_pr_evidence(project_id, issue_id)` MCP tool confirms the issue belongs to the supplied project and that each link matches the project's currently connected repository before making any GitHub call.
